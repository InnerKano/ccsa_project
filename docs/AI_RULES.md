# AI Collaboration Rules

Responsible AI usage protocol for this project. This is not a generic prompting guide: it defines what can be delegated, what requires mandatory human review, and how AI usage is documented.

---

## 1. Trust Levels

Not all AI-generated code deserves the same level of scrutiny. Classify each task before requesting it:

Green Level — delegate and review quickly:
- Includes: CRUD boilerplate, simple migrations, unit tests, UI components without business logic, docstrings, README.
- Rule: visual review before commit. Does not require understanding line by line.

Yellow Level — delegate and review in detail:
- Includes: endpoints with validation, business logic, database queries, error handling.
- Rule: you must be able to explain each decision without re-reading the code. Run locally before commit.

Red Level — AI proposes, you decide and verify:
- Includes: authentication, authorization, secrets/tokens handling, CORS, database permissions, anything that touches another user's data.
- Rule: never accept without complete reading. Never copy the entire block without rewriting at least the security parts to ensure you understand them.

If you don't know what level something falls into, treat it as Yellow by default.

---

## 2. Fixed Rules (non-negotiable)

1. No code in the **Red** zone is committed without being read line by line by a human.
2. No production configuration (`.env`, secrets, CORS, credentials) is generated and deployed without explicit manual verification.
3. Every database migration generated by AI is reviewed for: data loss, NOT NULL columns without defaults, and whether the `downgrade()` actually reverts the `upgrade()`.
4. If AI suggests a new dependency (library, package), verify that it exists, is maintained, and is truly necessary before installing it.
5. Never ask AI to "fix this" without first attempting to understand the error. The goal is to accelerate, not replace understanding of the system.

---

## 3. AI Usage Log (mandatory)

Every time AI contributes something non-trivial (Yellow or Red, or any architectural decision), add a line to `docs/AI_LOG.md` with this format:

```
YYYY-MM-DD | [module] | What was requested | How useful (1-5) | What was manually corrected
```

Example:
```
2026-07-05 | auth | Generate JWT login/refresh flow | 4 | Fixed: didn't invalidate tokens on logout
2026-07-05 | tasks | Migration for status column | 5 | No corrections needed
```

This log is not bureaucracy: it's direct input to answer "where did AI help the most? where did it fail?" with real evidence instead of memory.

---

## 4. What TO Delegate Aggressively

- Repetitive boilerplate (another CRUD endpoint following an existing pattern).
- Tests, including edge cases you forget by hand.
- Explanations of errors or stack traces before googling.
- First draft of documentation (README, API.md), then edited by hand.
- Mechanical refactors (renaming, extracting functions, typing).

## 5. What NEVER to Delegate Without Strict Control

- Deciding what data is sensitive and how to protect it.
- Permission logic (who can see/edit what resource).
- Anything the AI "assumes" about the data model without your explicit confirmation.
- Final production deployment configuration.

---

## 6. Before Each Commit

- [ ] I read and understand the code, not just pasted it.
- [ ] I ran the code locally (not just "looks good").
- [ ] If it touched the Red zone, I reviewed it line by line.
- [ ] If it contributed something relevant, it's recorded in `AI_LOG.md`.
